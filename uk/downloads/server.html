open.mp server — changes since v1.5.8.3079

Server operation and networking

  • Added artwork.show_crc_logs to enable TXD and DFF CRC logging when needed. It is disabled by default. #1164
  • Fixed environment-variable substitution in server configuration, including numeric and boolean settings. #1195
  • Fixed reloadbans so reloaded bans are enforced by the network again. Matching connected players are also removed. #1276
  • Fixed false “server is full” conditions after kicks, rejected invalid connection-lost packets, and temporarily banned invalid connection attempts to reduce log spam. #1209, #1173
  • Fixed connections attempted immediately after server startup being rejected by an invalid network cookie. #1213
  • Fixed broadcast RPC payloads being shortened when a plugin reads them before transmission. This affected features such as weather changes, messages, and game text. #1215
  • Fixed Linux shutdown hanging or crashing when the server runs without a terminal, such as under nohup. #1203
  • Vehicle paintjobs now reset when vehicles respawn. #1213

Scripting and components

  • Fixed %q escaping in Pawn format(), a crash when reading a missing console variable as a string, and crashes caused by invalid SetTimerEx arguments. #1159, #1171, #1223
  • Fixed spawning after leaving spectator mode and made TogglePlayerSpectating reliably enable spectating again. #1187, #1092
  • Changed main-script unloading so components reset after the script is unloaded, preventing callbacks and timers from referring to an unloaded script. #1190
  • Added usage messages when script-loading console commands are called without a filename, and clearer errors for missing legacy plugins. #1032, #1273
  • Added separate object and attached-object editing state checks, and validated incoming editing responses against the active edit mode. #1188
  • Fixed the syncRotation argument being ignored by AttachPlayerObjectToObject, including its C API path. #1163
  • Fixed C API gang-zone and pickup destruction failing to release their legacy IDs for reuse. #1231
  • Updated Pawn with fixes for memcpy and fwrite on packed strings, and corrected presets in the legacy server-side game-text component. #1180

NPCs

  • Added NPC_SetVehiclePos, NPC_SetVehicleRot, NPC_GetVehiclePos, and NPC_GetVehicleRot. Behavior change: NPC_SetPos now removes an NPC from its vehicle; use the vehicle-specific setter to reposition it while seated. #1182, #1237
  • Fixed NPC vehicles appearing flat or teleporting while driving on slopes, and improved vehicle movement synchronization. #1249, #1280
  • Fixed NPC_PutInVehicle leaving NPCs visibly on foot in boats. #1236
  • Fixed dead NPCs appearing standing when streamed in. NPC_Respawn now clears their death state. #1238, #1184
  • Fixed NPC infinite ammo when NPC_SetAmmo had not been called, corrected NPC_GetSkin’s return value, and fixed the angle calculated by NPC_SetAngleToPos. #1165, #1182, #1252
  • Improved movement between short NPC path nodes and prevented zero-time node transitions from repeatedly running in one tick. Movement change, transition limit
  • Fixed NPC cleanup and several crashes when optional components are missing or unloading. #1175, #1182

Building and deployment

  • Migrated builds to Conan 2 and added a dedicated build guide for Windows, Linux, and macOS. #1233, #998
  • Added macOS ARM build support and fixed Windows compatibility with newer Microsoft toolchains. #1234, #1235, #1166
  • Fixed the 32-bit Docker runtime image missing libraries required to start omp-server. #1263

v1.5.8.3079

Основне

  • Built-in server side fully controllable NPC
  • New C API / C API SDK and improved Pawn-to-SDK interoperability
  • Major network performance improvements with stronger sync validation checks
  • OpenSSL 3.0.13 upgrade
Переглянути повний список змін

What's changed

Major Features

  • Introdued fully controllable NPCs as a built-in server feature, removing the need for external NPC plugins and enabling deeper server-side AI and automation.
  • Added a C API and C API SDK, allowing developers to integrate open.mp directly with native code and external tooling.
  • Added the ability to call Pawn natives from the open.mp C++ SDK, significantly improving interoperability between scripting and native modules.

Networking & Performance

  • Significant network performance improvements, resulting in faster synchronization and more responsive gameplay.
  • Added multiple sync validation checks to prevent invalid data, spoofed states, and malformed packets.
  • MTU values are now validated against the maximum allowed per client version, preventing misconfiguration and instability.

Platform & Compatibility

  • Upgraded OpenSSL from 1.1.1 to 3.0.13, officially deprecating legacy Linux distributions and ensuring proper support for modern systems.
  • Added environment variable support for config.json, making containerized, CI/CD, and production deployments easier and more flexible.

NPC & Gameplay Improvements

  • NPC IDs now allocate from highest to lowest, preventing conflicts and improving predictability.
  • Deprecated ConnectNPC in favor of the new built-in NPC system.
  • Forced train creation to always use 4 consecutive IDs, fixing long-standing inconsistencies.
  • Fixed train passenger synchronization issues.

Stability & Bug Fixes

  • Fixed an infamous issue with spawn data
  • Fixed kick delay issues.
  • Fixed crashes related to gangzones in the checking list during server restarts.
  • Fixed random occurrences of player state being set to None after spectating.
  • Fixed stdin lock on Linux during server shutdown.
  • Fixed chatlogging not affecting death messages.
  • Removed the legacy Fixes component due to instability, redundancy, and its functionality being superseded by newer systems.
  • Numerous small Pawn native fixes for improved correctness and usability.

Documentation & Community

  • New and updated NPC scripting API (Pawn natives) are available in the official documentation: https://open.mp/docs
  • Join the community and get support on Discord: https://discord.gg/samp
  • Support development via OpenCollective: https://opencollective.com/openmultiplayer
  • Main website: https://open.mp/
